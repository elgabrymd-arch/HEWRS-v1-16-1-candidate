# HEWRS V1.20.0 — five-pass audit, research and implementation

## Assessment
V1.19.0's default Curated mode has a coverage limitation, not a scarcity of compatible garments. In this fresh all-wardrobe test, 31 of the 32 exact suit/blazer anchors returned only 1–3 curated outfits; S10 returned 14. Its optional broad heuristic returned 15 but retained hand-set ranking behavior that the owner dislikes.

V1.20.0 adds a distinct **Research-based wardrobe generator** as the normal local method. It composes new eligible combinations instead of filtering only 94 fixed references. It applies explicit contextual palette, value, pattern/focal and footwear guidance plus a small semantic reference prior. Curated and old heuristic modes remain honestly labelled alternatives. This is not the paused private visual-AI service and not a newly trained taste model.

Every one of the 18 suits and 14 blazers returned 15 in the new identical controlled test. True no-anchor Generate also returned 15. Counts do not prove aesthetic perfection or a universal guarantee under incompatible locks. The photos show the actual new choices and exact source IDs.

## How close is it to independent styling?
The current Curated records already incorporate examples the owner preferred; its principal defect is having too few alternatives per anchor. The old heuristic has enough coverage but cannot be equated with the assistant's independent visual judgment. Research-based generation now uses a quieter shirt/tie hierarchy, relative pattern scales, meaningful odd-jacket/trouser separation and contextual footwear. The small reference-structure term compares properties from the earlier preferred sets, not exact IDs or invented per-outfit approvals.

The resulting S01 top option is light-blue DS006 with brown/slate paisley T018 and dark-brown shoe-4. The old broad heuristic first chose the more conspicuous blue/gold T024 with DS029. This comparison is presented for visual judgment, not an objective proof that every new result is better. S10's new list retains lavender, cream/ivory, blue, pink, silver-grey, white-ground patterns and a chocolate No Tie alternative; no compulsory palette quota was imposed.

The new free Engine list uses 14 shirt IDs, 11 tie IDs (excluding No Tie), 9 shoe IDs and 1 No Tie option. Every unanchored physical ID remains at most twice. More unique IDs alone is not a quality score.

## What the web research does and does not support
Charles Tyrwhitt supports a focal garment, varied pattern scale, readable shirt/tie depth and tonal/adjacent/complementary palettes. Kamiceria supplies traditional navy/blue and brown/beige examples; its demographic skin-tone and rigid mixed-pattern prescriptions are not adopted. Boggi's regional guide reinforces readable tie contrast, but its warning about navy disappearing into navy is not a universal ban. HUGO BOSS relates shoe colour to dress level and tailoring shade; it explicitly permits cognac with navy and very dark brown/deep red with black. Crockett & Jones gives a specific suede-with-tailoring example. Jerem advocates deliberate separation and coherent material weight in odd-jacket outfits.

Those are selected primary sources—not “all designers” and not a scientific consensus. Their statements differ, and the source-to-rule record explains the disagreements. The family tables, numeric coefficients and resemblance prior are our engineering/styling judgments. No source claims or new prices/products are imported into the user's wardrobe facts. Full source URLs, qualifications and weights: `RESEARCH_RULES_V1_20_0.md` / `data/styling-research.json`.

## Preserved boundaries
All raw wardrobe/physical IDs, score tables, source index, assets, clothing geometry and renderer files remain unchanged. Original two-use rules and history/Favorites/weather modules are retained. The local mode preference has a new versioned key; the old key remains untouched for rollback. An existing explicit Visual preference remains unconnected and is not silently billed or substituted. No private AI setup was resumed.

Source assessments lacking an applicable score remain held rather than receiving invented numbers. This release improves selection from the supported scored pool; it does not silently resolve historical premise conflicts. The Curated mode continues to return its real finite count, never reference-labelled filler. No appearance was globally banned because it is brown, dark, lavender, checked, suede or cognac.

## Evidence boundary and development attempts
These were local source/Node and memory-loaded Chromium tests with actual garment files and isolated synthetic storage. Weather permission/provider success was represented by declared fixtures in regression tests. They are not new tests of the currently hosted site, a physical iPhone, or private paid AI. No owner history/Favorites data was accessed.

The mounted V1.19 full-source ZIP was truncated and was not used. The baseline was restored from the already-mounted V1.17.1 source and verified successive updates. Its complete source manifest matched the original V1.19 receipt (2026 payloads; manifest SHA-256 `933701991f827e7e25c269bfecb10fc7f38e86399b9f9adc06ade02f2731575f`). This is exact source identity, not a fresh verification of the unavailable intact original ZIP-container hash.

An exploratory pre-reference-prior Node run was stopped and superseded by the full final rerun. An initial two-page Chromium attempt crashed during PNG capture under memory pressure while the large Node matrix was running; the fixture was rerun with sequential per-selection image loading after that matrix. Neither partial attempt is counted as a completed passing audit. A later long-lived two-page run stopped during the S11 fixture; final rendering was rerun with bounded per-topwear browser-page lifetimes. A method-aware family-filter regression found that an object-spread wrapper captured a getter at construction; the accessor was replaced with an explicit method callback, and all supported shirt/tie family filters were retested. One fixture used the wrong historical revision string, which was corrected to the existing module's literal revision. A partially completed browser run was then discarded and the final full suite rerun after that adapter correction. Attempt records are retained. Final runtime scripts are pinned in TESTED_RUNTIME_SHA256.json. An initial rollback check caught an omitted baseline CHANGED_FILES.json copy in the packaging preparation; original ledger bytes and protected-file classification were corrected before final replay. That failed preparation is not included as a passing check.

## Install and rollback
Use the new V1.19.0 → V1.20.0 update, not an older same-project ZIP. Copy contents of FILES_TO_COPY into the existing candidate root, retaining other files and .git. No private server or API setup is required. Commit:

`V1.20.0 — broad 15-option generation with researched styling`

Home → Style → Stylist settings: **Research-based wardrobe generator — local (up to 15)**. Exact topwear selections remain anchors only for that garment. Clear locks only when actually testing unrestricted Engine Choice; do not clear browser storage.

`python -B tools/verify_v1200.py` verifies exact installed source. `python -B tools/rollback_v1200.py --output NEW_FOLDER` reconstructs exact V1.19.0 with its prior defaults in a separate destination without touching browser data. The new mode key is ignored by old code. New-generation session fields use existing formats.

No GitHub upload or deployment was performed. This is an audited local release candidate addressing the identified coverage/ranking issues, not a claim of universally final taste or defect-free software.
